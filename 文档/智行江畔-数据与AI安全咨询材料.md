## 一、项目简介（1 分钟版本）

**智行江畔**是面向江西财经大学新生的校园生活智能助手，把「搜问题、看地图、办事情、查人流」集成到一个涂鸦风单页应用里：

* **四章结构**：询问（首页 AI 搜索）→ 地图（高德 2.5D）→ 数字孪生（3D 人流可视化）→ 指南（办事/医保/校历）。
* **技术形态**：纯静态前端，`index.html` 双击直开；无自建后端数据库，所有用户数据只存**浏览器 localStorage**（前缀 `zxsj66\\\_`）。
* **AI 能力**：接入 DeepSeek（`deepseek-chat`），经团队部署的**服务端代理**调用，前端不持有 API Key。
* **数据来源**：64 个校园点位（静态）、拥挤度**纯函数模拟引擎**（可选导入实测人流 JSON）、问卷双口径（真实 34 份 + AI 模拟 75 份）。
* **部署**：GitHub Pages（前端）+ Cloudflare Pages Functions / Render / Node（DeepSeek 代理，三选一）。

### 数据流向（文字版）

```
用户浏览器 ──(问题)──▶ 前端 ai-service.js ──(POST /ai, X-App-Key)──▶ 服务端代理
                                              │                        │ 校验 APP\\\_SECRET
                                              │                        ▼
                                              │                   api.deepseek.com
                                              │                        │
                                              ◀──(回答，过滤后)─────────┘
用户数据：搜索历史 / AI 对话历史 / 投票 / 偏好 —— 仅存 localStorage，不上传
第三方：高德地图 JS API、D3、ECharts、MediaPipe（手势）、Google Fonts（字体）
```

## 二、当前已做的安全措施

|类别|已实现|位置|
|-|-|-|
|AI Key 保护|DeepSeek Key 只存服务端环境变量 `DEEPSEEK\\\_KEY`，前端不持有|server.js / worker.js / functions/ai.js|
|代理鉴权|前端请求头 `X-App-Key` 与服务端 `APP\\\_SECRET` 比对，不匹配返回 403|functions/ai.js|
|高风险拦截|自杀/自伤类关键词 → 阻断并返回 12356 心理援助热线话术|ai-service.js `hitHighRisk`|
|中风险降级|敏感词 → 「安全回答模式」并加角标|ai-service.js `hitMidRisk`|
|医疗过滤|回答含「诊断/开药/处方/剂量」等词 → 替换为校医院建议话术，明确不作诊断|ai-service.js `filterMedical`|
|频率限制|客户端 10 秒内最多 3 次|ai-service.js `rateLimited`（**仅前端**）|
|超时控制|60s AbortController 兜底|ai-service.js|
|存储规范|全站 localStorage 统一 `zxsj66\\\_` 前缀，键名白名单化|app.js `LS` 常量|
|数据诚信|问卷对外引用只用真实 34 份，AI 模拟样本常驻角标|survey-data.js|
|断网检测|地图/AI 依赖网络的操作做 `navigator.onLine` 预检|app.js|

## 三、自评：当前风险点与待改进项

> 以下是我们已识别、但尚未解决（或解决不彻底）的问题，供工程师逐条评估。

1. **前端"伪密钥"硬编码**：`AI\\\_CONFIG.APP\\\_KEY = 'zhixuejiangpan2026'`、高德 `securityJsCode`、和风天气 `KEY` 都写在前端源码里，任何访问者可见。它们不是真正的机密，但**鉴权强度 ≈ 无**，需要明确"这些暴露是否可接受、该换成什么方案"。
2. **限流仅客户端**：`rateLimited()` 在浏览器里，改写 JS 即可绕过；**服务端没有独立限流、审计、黑名单**，存在滥用/刷接口/打爆 Key 的风险。
3. **AI 对话历史明文存 localStorage**：`zxsj66\\\_aichat`（最多 10 条，含用户问题与 AI 回答）未加密、无脱敏；虽有「清除对话历史」按钮，但**无自动过期、无退出即删**。
4. **摄像头权限无显式说明**：手势控制用 `getUserMedia`，但**无隐私提示、无用途说明、无单独同意**（只靠浏览器原生授权弹窗）；视频流仅本地处理（MediaPipe），但未向用户明示。
5. **第三方脚本无完整性校验（SRI）**：高德、D3、ECharts、MediaPipe CDN、Google Fonts 均裸引，若 CDN 被劫持可注入恶意代码。
6. **实测人流数据导入**：`zxsj66\\\_realdata` 允许导入 JSON。目前是聚合计数（非个人），但**若日后接入真实摄像头/门禁数据，将触及个人信息边界**，需前置界定。
7. **学生群体合规**：用户主体为大学生（含可能未满 18 岁的新生），涉未成年人个人信息与敏感个人信息（位置、健康咨询记录），PIPL/《儿童个人信息网络保护规定》有更高要求。
8. **生成式 AI 合规**：DeepSeek 属生成式 AI，按《生成式人工智能服务管理暂行办法》公开服务有**备案、内容标识、投诉举报、安全评估**等要求（当前为参赛 demo，未走流程，需知晓差距）。
9. **无隐私政策 / 用户协议 / 同意机制**：全站无「隐私政策」「个人信息处理规则」「撤回同意」入口，首访即写 localStorage。
10. **代理 CORS 全放开**：`functions/ai.js` 返回 `Access-Control-Allow-Origin: \\\*`，任意网站可跨域调用我们的 AI 代理（即使有 APP\_KEY 也弱）。

## 四、想请教的问题

## A. 密钥与凭据管理

1. 前端 `APP\\\_KEY`、高德 `securityJsCode`、天气 Key 这类"必然暴露"的值，正确姿势是什么？是否应改为「每用户/每次会话临时凭证 + 服务端签名 + 短时效」，还是对公开 demo 直接接受？
2. Serverless（Cloudflare Pages Functions / Render）环境下，`DEEPSEEK\\\_KEY`、`APP\\\_SECRET` 的**轮换、最小权限、审计**怎么做最稳妥？Key 泄露后的应急流程？
3. 高德 JS API 的 `securityJsCode` 到底防什么、防不了什么？它的白名单域名机制能否作为"别人盗用我们 Key"的有效防线？
4. 若要给 3 条「密钥分级」红线（哪类永远不能进前端、哪类可以、哪类必须服务端持有），你会怎么分？

### B. AI 安全与合规

5. 面向学生的 AI 助手，除了我们已有的敏感词/医疗过滤，还缺哪些**提示注入（prompt injection）、越狱、诱导输出**防护？服务端要不要做输入/输出双过滤？
6. 客户端限流必然可绕过，服务端该加哪些**限流 + 审计 + 内容留痕**（但又不采集个人对话内容，避免把隐私搬上服务器）？如何在"安全"与"最小化"之间取舍？
7. DeepSeek 这类第三方大模型：**数据是否会出境/留存？** 提交给模型的对话内容从 PIPL 角度看算不算"向第三方提供个人信息"？需要向用户披露什么？
8. 生成式 AI 公开上线的**备案/安全评估/内容标识/投诉机制**，对一个参赛 demo 和未来真实上线，分别的最低门槛是什么？
9. 我们的"敏感词分级 + 医疗替换话术"设计，从专业角度是否足够？有没有标准词库/成熟方案可复用？

### C. 数据存储与最小化

10. localStorage 里存的搜索历史、AI 对话历史、投票、偏好，**哪些可以留、哪些应该加密、哪些应该缩短保留期或改为"会话级"（关页即清）**？
11. AI 对话历史明文存储：是否需要加密（Web Crypto）？还是更简单的"本地哈希/脱敏/只存最近 3 条"？**用户"删除权"**（撤回同意）我们目前只有按钮，够吗？
12. 实测人流数据若升级为真实摄像头/门禁数据，**从"聚合计数"滑向"个人信息"的边界在哪里**？最小化该做到什么粒度（匿名化、K-匿名、聚合到分钟/时段）？
13. 我们所有数据都在浏览器、无后端库——这种"零服务端数据"架构，本身是不是最好的隐私设计？有哪些**合规声明**能把它变成答辩亮点？

### D. 隐私与同意

14. 首访即写 localStorage、首访即调 AI——需要怎样的**首屏同意/隐私政策**？"继续使用即视为同意"这种默示同意在大陆语境下够吗？
15. 面向大学生（含 18 岁以下新生）的**未成年人保护**：需要额外做什么？健康/心理类问答记录算不算敏感个人信息？
16. 隐私政策文档自己写风险高，**标准模板/必备条款清单**能给一份吗（收集项、用途、留存、第三方、撤回、投诉）？

### E. 供应链与前端安全

18. 高德/D3/ECharts/MediaPipe/Google Fonts 裸引 CDN，\*\*SRI（子资源完整性）\*\*和 CSP 该怎么加？加完会不会和"双击 file:// 直开"冲突？
19. 前端整体还有哪些常见坑：**XSS 面**（我们把用户/AI 文本拼进 innerHTML 时已用 `esc()` 转义，是否还有遗漏）？CSP、点击劫持、外链策略？
